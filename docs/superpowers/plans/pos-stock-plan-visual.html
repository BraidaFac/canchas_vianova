01 — Decisiones de arquitectura
# Decisión Elección Razón
1 Vista financiera Sección Cobros — nueva Todos los ingresos agrupados por reserva/consumo, expandibles a pagos individuales. Muestra efectivo + transferencia.
2 Vista fiscal Sección Comprobantes — sin cambio conceptual Solo documentos ARCA con CAE. "Comprobante" = factura fiscal, no mezclar con cobros en efectivo.
3 Pagos split (efectivo + transfer) Tabla pagos polimórfica Una reserva puede tener N pagos. La emisión de factura siempre parte de un pago_id con medio_pago='transferencia'.
4 Multi-entidad fiscal config_facturacion → entidades_fiscales multi-row Los datos actuales son de testing; migración limpia sin deuda técnica. Campo predeterminada para la entidad por defecto.
5 POS UI Dos vistas alternables (Grid / Lista) Cada empleado elige la que le resulta más cómoda. Toggle persistido en localStorage.
6 Módulos deshabilitables Tabla config_modulos — fila única con bools Igual al patrón de facturacion. El sidebar oculta módulos con flag false. Toggles en Configuración (superadmin).

09 — Plan de implementación
1
Migración de base de datos
Nueva migración SQL: rename config_facturacion → entidades_fiscales, crear cuentas_bancarias, pagos, iva_alicuotas, categorias, productos, producto_precios, consumos, consumo_items, compras, compra_items. Modificar comprobantes (pago_id, origen_tipo). Seed de alícuotas IVA.
2
Refactor facturación multi-entidad
Actualizar afip-client.ts y emitir.ts para recibir entidad_fiscal_id vía pago_id. Nuevas APIs: entidades-fiscales, cuentas-bancarias, pagos. Actualizar tipos en lib/facturacion/types.ts.
3
UI Configuración — multi-entidad
Sección Facturación en Configuración: CRUD entidades fiscales, CRUD cuentas bancarias, CRUD alícuotas IVA. Migrar la UI existente de config_facturacion a este nuevo CRUD.
4
Pagos split en Reservas
Panel de cobro en vista de reserva: agregar N medios de pago, seleccionar cuenta bancaria para transferencias. API POST /api/admin/pagos. Trigger automático de emitirFactura() para pagos por transferencia.
5
Módulo Stock
Página /admin/stock con tabs: Productos (tabla edición inline, historial precios), Categorías (CRUD inline), Compras (registrar compra con cálculo IVA automático y actualización de stock).
6
Módulo POS
Página /admin/pos: layout catálogo + carrito. Vista Grid (tabs de categorías + cards). Vista Lista (buscador). Toggle persistido en localStorage. Panel de cobro inline con pagos split. Opción de asociar a reserva. API consumos.
7
Actualizar Comprobantes
Actualizar ComprobantesTab: columna Origen (Reserva/Consumo), columna Cuenta bancaria, filtro por origen. Validar que reservas 100% efectivo no aparecen.
8
Sidebar + QA
Agregar Cobros, POS y Stock al sidebar. config_modulos: props al sidebar para ocultar módulos inactivos. Toggles en Configuración (superadmin). Prueba del flujo completo: reserva cobrada mixta → Cobros muestra fila expandible → comprobante ARCA correcto. Venta POS → consumo + comprobante. Compra → stock actualizado.
